# PRD × Figma 审计整改说明

日期：2026-09-21（复核版已同步）  
依据：[PRD-Figma审计报告.md](../PRD-Figma审计报告.md) 与《多 Harness AI 开发团队协作平台 PRD》V1.0。  
Figma：[完整文件](https://www.figma.com/design/C1roCB6shYmzP6oEu5ZAs4)。

## 审计内容完整性核对

审计报告对原型覆盖面的判断成立：首版已经完成 Role、Binding、Task、Workspace 的核心展示和少数关键路径，但不足以支持 MVP 的控制闭环。报告列出的 P0 缺口与 PRD 第 8～18、20、22、25 节一致，尤其是任务状态、Run、失败、依赖、审批、审计和恢复。

“Role-to-Role 非即时通信”属于值得纳入 MVP 的必要扩展，但需要准确说明其来源：PRD 6.12 仅预留 Message 作为短指令、提醒或人工备注，并未定义报告中提出的完整线程信封、投递状态机与 Binding 快照字段。本次原型按报告设计了该能力；后续应把报告第 6 节的消息模型正式补入 PRD/协议文档，再进入接口设计。

## 复核版二轮整改

针对复核版提出的通信闭环问题，新增了三个可点击画板：

- [状态变更通知](https://www.figma.com/design/C1roCB6shYmzP6oEu5ZAs4?node-id=29-731)：TASK_REVIEW_REQUESTED 等事件经订阅策略生成消息，在路由时解析目标 Role 的当前 Binding；同时定义旧 Binding 拒收、新 Binding 接管与 NEEDS_HUMAN 规则。
- [QA 回复 Leader](https://www.figma.com/design/C1roCB6shYmzP6oEu5ZAs4?node-id=29-732)：以 ANSWER 回复同一线程，保留 reply_to、Task、Reference 与 Workspace 决策文件。
- [回复已送达](https://www.figma.com/design/C1roCB6shYmzP6oEu5ZAs4?node-id=29-733)：展示 MESSAGE_REPLIED → QUEUED → ROUTED → DELIVERED 和对应的审计 Event。

岗位通信页已增加“以 QA 身份回复”操作；活动审计页已补 MESSAGE_ROUTED 与 MESSAGE_REPLIED 示例；所有桌面页的“待我处理”计数已同步为 4，执行异常入口不再隐藏在独立画板中。

## 第二轮复核后的继续整改

本轮将复核版剩余的可操作缺口收口为以下设计和协议基线：

- [活动与审计](https://www.figma.com/design/C1roCB6shYmzP6oEu5ZAs4?node-id=13-357) 现以 `THREAD-001` 展示 `MESSAGE_SENT`、`MESSAGE_ROUTED`、`MESSAGE_DELIVERED`、`MESSAGE_ACKNOWLEDGED`、`MESSAGE_REPLIED` 与 `MESSAGE_NEEDS_HUMAN` 的完整可回放链，并保留 Task、Role、Binding、Adapter、Run 与 Artifact 关联。
- 新增 [通知订阅与投递策略](https://www.figma.com/design/C1roCB6shYmzP6oEu5ZAs4?node-id=45-806)：可查看/保存按事件、岗位、严重级别和范围配置的订阅规则；同时呈现 5 分钟去重、最多 3 次指数退避和无有效 Binding 的升级规则。`状态变更通知` 画板已可点击进入。
- 新增 [换绑期间待投递消息](https://www.figma.com/design/C1roCB6shYmzP6oEu5ZAs4?node-id=46-815)：明确已送达不回收、入队消息保留 Binding 快照、投递时解析当前 Binding、旧 Binding 拒收后的重试，以及 `NEEDS_HUMAN` 的授权改派边界。`换绑待生效` 画板已可点击进入。
- 清除了 41 条指向旧组件节点的悬浮反应；不影响原有点击导航。当前仍保留 3 条指向有效组件变体的 Hover。
- PRD 14.2 已正式补入 Message / Thread 操作，且定义至少一次投递、幂等、订阅、Binding 快照和历史不可改写的约束。

## 第三轮复核后的继续整改

- 新增 [Harness 注册与健康检查](https://www.figma.com/design/C1roCB6shYmzP6oEu5ZAs4?node-id=59-839)：展示实例名称、Adapter、位置、能力、健康检查结果和凭据安全引用；不展示任何明文凭据。连接列表的健康检查与诊断可进入该页，结果页可返回连接列表或查看审计。
- 为完整任务表单、验收与退回、Run 失败、依赖与冲突、高风险审批、Run 对账、消息重试/改派和换绑待投递行级处理补齐正式点击路径。每个主操作均进入相应结果、后续处置或人工接管画板，而非仅停留在静态按钮。
- 通知订阅策略改为覆盖 11 类默认事件分组：任务分配、验收、受阻、依赖满足、运行失败、超时、Harness 离线、审批、换绑、冲突和结果过期。
- 新增 [消息投递终态](https://www.figma.com/design/C1roCB6shYmzP6oEu5ZAs4?node-id=64-848)：区分 `RETRYING` 瞬态、`FAILED` 和 `EXPIRED` 终态，提供重新排队、授权改派、新建后续消息、审计和策略入口。
- PRD 6.12 已定义 `RETRYING` 的状态回流及 `FAILED / EXPIRED` 的保留、TTL 和审计规则，消除原型与协议的状态命名歧义。

## 仍待下一轮补齐

- 全局设置、通知订阅、安全审计导航、完整的 Binding 历史和 Harness 连接配置表单。
- 实际可编辑的筛选、拖拽、输入、字段错误、加载、断连、引用失效与并发更新冲突交互。
- 完整移动端任务详情、审批、通信与恢复闭环。
- 无障碍的真实实现验证：键盘焦点、读屏提示、减少动态效果和对比度测试。
- Role-to-Role 消息的协议正文、幂等/重试 API、权限矩阵和通知订阅规则写入 PRD 与后续接口设计。

## 验证

Figma 当前共 36 个画板。已检查：直接子层无越界、610 个可见文字均使用 Noto Sans SC、129 条 Node 原型反应的目标均存在；其中 12 条 Hover 均指向有效组件变体。该检查验证的是可编辑原型结构和基本视觉边界，不等同于浏览器端、服务端、真实 Adapter 或无障碍验收。
