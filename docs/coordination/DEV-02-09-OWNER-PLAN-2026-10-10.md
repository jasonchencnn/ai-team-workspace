# DEV-02-09 可信安装 Owner 身份实施计划

Human 于本轮明确接受 ADR-0007 第 1 条，其他六条仍 Proposed。Codex 主控串行执行和第二遍反例，不新增外派、费用或外部服务。节点仍 BLOCKED，最终验收后再判断。

## 来源与边界

现 host/security 无 Owner 持久来源。本轮采用 Tauri 原生启动解析的当前安装 app-local-data 根目录，保存固定名称的版本化身份文件与初始化标记；标识由 OS 随机源与注入时钟生成 UUIDv7，只有原生初始化代码可初始化，IPC/Adapter 不提供 ID 或路径。UUID 是安装控制者的应用身份标识，不是自然人实名认证或从系统用户名推导的身份。

空安装首次初始化；已有资料但缺身份、初始化中断、损坏、symlink、不安全权限、运行期记录替换/删除均默认拒绝，不从旧 Notification/Role/UUID 排除推定 Owner、不自动重置身份。初始化标记用于区分首次初始化与身份记录丢失。实例正常重启读取同一记录，后续解析复核同一 ID。文件仅当前本地账户访问，威胁边界与本地数据库一致，不宣称能防同账户恶意修改全部本地数据或 OS 管理员攻击。

Application 只声明受信身份端口及相同 Notification/Policy recipient 能力；不将 actor 声明当授权。Security 实现文件来源，Desktop 只装配并保存原生状态，不添加 IPC 命令。旧通知的任意 ID 不自动归并；未来迁移需明确的 Human 映射证据。完整过滤/提醒/mandatory/解决语义仍待决，11 类通知用例按 05-08 准入。

## 写集与验证

1. 记录部分接受，冻结规格仅添加已接受身份条款引用。
2. 新增 Application 身份端口、Security 文件来源及 Desktop 启动装配；必要内部 dependency 边由主控串行调整 manifest/lock，不更换外部版本或技术栈。
3. 在真实临时文件系统验证首启、重启、并发、失败、权限/路径与身份失效；以真实 SQLite 行验证相同 recipient 与 Role/任意 UUID 不混淆。权限拒绝的业务事件留待真实命令执行点，不声称纯解析器已实现拒绝审计。
4. 第二遍反例、恢复 SHA、对应测试/静态检查；当前输入完整 Mac21 和 C7 补测、输出后 SHA/secret scan；最后同步审查与节点状态。
