# 节点审核、阶段门禁与验收标准

> 版本：1.0  
> 规则：节点专属标准见 `DEVELOPMENT_NODES.md`；本文件的通用标准与阶段门禁同样强制。

## 1. 完成定义

一个开发节点只有满足以下全部条件才能从 `REVIEW` 进入 `DONE`：

1. 范围：仅实现节点声明的目标，没有隐式扩栈、顺手重构或未登记行为变化。
2. 需求：关联至少一个 FR、AC、审计项或基础设施目标；行为与事实优先级一致。
3. 架构：依赖方向、模块边界和领域不变量未破坏；偏差有已接受 ADR。
4. 数据：迁移、兼容、事务、幂等、版本和恢复影响已说明并验证。
5. 安全：权限在可信边界重算；秘密、路径、进程、日志和错误按规范处理。
6. 体验：成功、加载、空、失败、断连、权限、冲突等适用状态完整，不用静态成功页代替结果。
7. 测试：按风险完成单元、性质、集成、契约、组件或 E2E；相关检查全部通过。
8. 可观察：关键操作具备结构化 Event/日志/correlation ID，且不泄露敏感值。
9. 文档：协议、Schema、错误码、运行方式或操作行为改变时同步文档。
10. 证据：交付记录包含命令、结果、测试报告或截图/录屏、遗留风险与回退方式。

“代码已写完”“页面能点”“Happy path 能跑”均不等于节点完成。

## 2. 通用审核门禁

| Gate           | 审核内容                           | 通过标准                                  | 阻断示例                           |
| -------------- | ---------------------------------- | ----------------------------------------- | ---------------------------------- |
| G0 范围        | 节点、依赖、输入与非目标           | 节点 ID 明确，依赖 DONE，变更面与节点一致 | 混入无关重构；需求仍有两种解释     |
| G1 构建        | 安装、编译、生成物、锁文件         | 干净环境可复现；无未提交的生成漂移        | 只在开发者机器可构建               |
| G2 静态质量    | fmt、lint、typecheck、clippy       | 零错误、零告警；无无理由 suppress         | `any`、`unwrap`、ignore 掩盖问题   |
| G3 行为测试    | 单元/性质/集成/契约/组件/E2E       | 与节点风险匹配；成功和关键失败均覆盖      | 只有快照或只测 happy path          |
| G4 数据一致性  | migration、事务、版本、幂等、恢复  | 失败零副作用；竞争有确定结果；迁移可恢复  | 最后写入者覆盖；重复产生 Run/Event |
| G5 安全        | 权限、路径、进程、凭据、日志、依赖 | 默认拒绝；Human-only 不可绕过；无秘密泄露 | UI 隐藏按钮代替服务端授权          |
| G6 UX/A11y     | 状态、文案、键盘、读屏、窄屏       | 操作可理解、可恢复；适用 WCAG 2.2 AA      | 颜色为唯一状态；错误吞掉表单输入   |
| G7 可观察/审计 | Event、日志、关联、脱敏            | 关键行为可追溯，失败原因稳定且不泄密      | 只写自由文本日志；无 actor/request |
| G8 性能/资源   | 热路径、进程、文件、查询           | 不超过预算；后台任务可取消与关闭；Adapter 进程按 ADR-0006 的平台和获准入口责任边界验收 | 未通过准入的脱组后代存活；无界日志/输出/查询 |
| G9 文档/证据   | 说明、测试结果、风险、回退         | 另一位执行者可据此复现和继续              | 口头声称通过；无测试环境信息       |

适用性由节点决定，但 G0/G1/G2/G3/G9 永远不能标记为“不适用”。

## 3. 风险分级与审核模型

| 风险级别 | 典型变更                                                                  | 执行/审核要求                                                            |
| -------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| R3 关键  | 权限、凭据、迁移、状态机、租约、fencing、恢复、Adapter 协议、审计不可变性 | `gpt-5.6-sol` 执行；必须进行独立复核或第二遍反例审查；至少一种失败注入。 |
| R2 重要  | 业务用例、跨模块 IPC、Task/Run UI 控制、Workspace 写入、通知路由          | `gpt-5.6-terra` 或节点指定 `sol`；集成测试 + 负向用例。                  |
| R1 常规  | 只读查询、常规表单、列表、基础组件                                        | `gpt-5.6-terra`；组件/集成测试。                                         |
| R0 机械  | 脚手架、Token、生成物检查、纯文档                                         | `gpt-5.6-luna`；至少构建/链接/一致性检查。                               |

一旦发现实际风险高于原节点，升级模型与审核要求，不降低门禁。

2026-09-24 Human 接受的 ADR-0004 仅替换 Wave 2 尚未开始节点的执行模型路由；本表的风险分类、独立复核/失败注入及 G0～G9 仍强制。Gemini 的阶段自验收不等于正式节点 `DONE` 或总控最终验收。

## 4. 阶段门禁

### Gate A：开发准入（DEV-00 出口）

必须满足：

- Human 接受 ADR-0001；
- FR/AC/审计/Figma 追踪矩阵无 P0 孤儿项；
- Task/Run/Binding/Message/Approval 状态表和权限矩阵评审通过；
- Adapter V0、错误码、ID/时间/版本规则冻结；
- 未决项有明确 owner，且不影响基础架构。

阻断：Human Notification/Role Message 仍混用、TODO/READY 未分离、权限只定义到 UI。

### Gate B：底座可用（DEV-01 出口）

必须满足：

- 干净环境完成 install/build/test；
- 按 ADR-0005，以当前最终输入在 macOS ARM64 实机运行完整 21 项门禁并形成可校验证据；保留输入总哈希、前后快照一致性、全 refs 历史秘密扫描、工具版本与来源证明及失效规则。Ubuntu/Oracle 不再阻断 Mac 节点；零预算阶段本机证据替代尚未运行的 hosted checks，不能声称已有 branch protection 服务端强制；
- Tauri capability 最小化；
- Rust Schema → TypeScript 生成无漂移；
- 日志脱敏测试通过。

### Gate C：领域事实源成立（DEV-02 出口）

必须满足：

- 所有 migration、约束和回滚测试通过；
- 状态机合法/非法迁移与性质测试通过；
- 权限求交、乐观锁、幂等和 Outbox 竞争测试通过；
- 备份/恢复完成一次演练；
- Rust domain/application 行覆盖率 ≥ 90%、分支 ≥ 85%。

### Gate D：Adapter 可控（DEV-03 出口）

必须满足：

- Mock 契约测试全绿；
- 成功、失败、超时、重复、乱序、崩溃、晚到事件均已注入；
- 旧 fencing token 的 heartbeat/output/completed 全部拒绝；
- Codex Spike 有启动、输入、状态、取消、结果、隔离、恢复证据；
- 第二真实 Harness 决策有 Go/No-Go 记录。

### Gate E：Workspace 不静默覆盖（DEV-04 出口）

必须满足：

- path traversal/symlink/越权路径测试通过；
- 两个 Run 的 worktree 隔离和清理验证通过；
- 非 Git 第二写者稳定拒绝；
- stale baseline、同文件冲突和上游重开有显式状态；
- Artifact 能追到 Role、Run、版本和基线。

### Gate F：应用契约完整（DEV-05 出口）

必须满足：

- 所有 P0 命令和查询有类型化 IPC 契约测试；
- 关键命令均携带 actor/request/idempotency/version；
- 错误码与 UI 可操作提示一一映射；
- 查询无明显 N+1，游标分页稳定；
- UI 无需直接访问 DB、Git、Keychain 或 Adapter。

### Gate G：Human 可用（DEV-06 出口）

必须满足：

- Figma 核心画板对应功能均由真实数据驱动；
- 加载、空、错误、断连、权限、版本冲突、引用失效状态齐全；
- Task/Run、Role/Harness、Event/Message/Notification 概念不混淆；
- 键盘完成创建 Task、审批、发送消息和重试；
- 窄屏可处理失败 Run、审批和消息异常；
- axe 无 critical/serious，手工焦点与读屏检查通过。

### Gate H：MVP 主链成立（DEV-07 出口）

必须满足：

- AC-01～AC-12 全部具备端到端证据；
- 并发、失败、换绑、权限、重启、接管和审计用例均使用真实基础设施边界；
- 没有通过清库、关闭权限或跳过 Adapter 来“通过”的测试；
- 任一 DONE Task 可回放完整证据链。

### Gate I：候选版本（DEV-08 出口）

必须满足：

- 当前 macOS 平台的全部适用 required checks 绿，并有最终输入的本机证据；
- 性能、安全、恢复、无障碍报告通过；
- 安装/卸载、空库初始化、上一 schema 升级、备份恢复均验证；
- macOS 14+ 支持声明须有最低支持版本及首发目标架构的真实桌面证据；当前开发机单一系统版本不能代替；
- P0 无阻断缺陷；R3 缺陷为 0；
- 已知限制与实际支持平台一致，不夸大能力。

Linux、Windows 或其他 Mac 架构的测试/上线标准在首个 Mac 版本通过本 Gate 且 Human 作出发布决定后，按 ADR-0005 单独建立；这些平台当前不是 Gate I 的阻断项。

## 5. 测试金字塔与最低要求

| 层级                       | 目标                 | 必测内容                                               |
| -------------------------- | -------------------- | ------------------------------------------------------ |
| Domain unit/property       | 快速证明不变量       | 状态迁移、权限求交、DAG、TTL、重试、fencing、幂等语义  |
| Persistence integration    | 证明真实 SQLite 行为 | migration、外键、唯一约束、事务回滚、版本竞争、Outbox  |
| Contract                   | 证明边界兼容         | IPC Schema、Adapter JSON-RPC、错误 envelope、版本协商  |
| Infrastructure integration | 证明真实本地能力     | Git/worktree、路径、Keychain 替身、进程取消/崩溃、备份 |
| UI component               | 证明交互和可访问性   | 表单、Dialog、状态、键盘、错误、焦点、axe              |
| Desktop E2E                | 证明用户闭环         | AC-01～12、重启、断连、失败注入、真实桌面权限          |

测试不得依赖公网、真实生产凭据或不可重放的用户会话。真实 Harness Spike 与稳定 CI 套件分开，CI 使用 Mock Adapter。

## 7. 关键测试场景清单

以下场景不得只靠人工点选：

- 两个调用使用同一 idempotency key、相同 payload；
- 同一 key 但不同 payload；
- 两个 expected_version 同时更新一个 Task；
- 两个 Run 同时 claim 同一 Task；
- lease 过期后旧 Run 晚到 heartbeat/output/completed；
- Task 依赖形成直接环与多跳环；
- DONE 上游重新打开后下游变陈旧；
- 换绑期间 QUEUED Message、已 DELIVERED Message 与旧 Adapter 拒收；
- Message 重试上限、TTL 过期、授权改派、未绑定 Role；
- 平台在事务提交前、提交后/Outbox 消费前、Run 进行中崩溃；
- Workspace symlink 指向授权根外；
- Git dirty workspace、worktree 创建失败、冲突与清理失败；
- Keychain 不可用、凭据引用失效、日志包含测试秘密；
- Notification 去重窗口与 Event 不丢失；
- 大量 Event 游标翻页时新 Event 插入；
- UI 断连、返回 409 版本冲突、失效引用与权限拒绝后恢复。

## 8. 性能预算

| 指标                        |        P0 预算 | 测量要求                                     |
| --------------------------- | -------------: | -------------------------------------------- |
| Task 列表/详情              |  本地 P95 < 2s | 1 万 Task/Event 数据；含 IPC 与渲染。        |
| 任务分配到在线 Adapter 可见 |      P95 < 10s | 含 Outbox、路由与 Adapter 确认。             |
| 并发 Run                    |              5 | 同时心跳、输出和取消，不丢事件。             |
| 启动恢复扫描                |      目标 < 5s | 1 万记录、5 个未终结 Run；超标需报告。       |
| UI 主线程长任务             |         < 50ms | 关键页面性能 trace；大列表虚拟化按数据决定。 |
| 日志                        | 14 天或 200 MB | 自动轮转；不影响审计 Event。                 |

性能优化不得破坏审计、权限或一致性；未测量前不引入缓存层。

## 9. 安全验收

必须验证：

- Adapter 参数不经 shell；恶意标题/路径不能形成命令注入；
- `..`、symlink、绝对路径、设备路径和大小写差异不能越权；
- Harness 无法绑定自己、提升 Role 权限或批准自己的高风险请求；
- 旧 Binding、过期 Approval、旧 fencing token 不能恢复能力；
- SQLite、日志、Event、导出、崩溃报告和 UI 都不含真实秘密；
- Tauri capability 只开放已声明命令和资源；
- Adapter 输出受大小、频率、Schema 和顺序限制；
- 依赖许可证和已知高危漏洞为 0 个未豁免项；豁免必须有到期日和补救计划。

## 10. 可访问性验收

- WCAG 2.2 AA 作为目标；自动检查只是下限。
- 创建 Task、审批、发送/回复消息、失败重试四条流程全键盘完成。
- Dialog 打开后焦点锁定，Esc 行为、关闭后返回焦点正确。
- 表单错误通过文本和 `aria-describedby/live region` 传达；不只改变颜色。
- 状态标签对读屏包含真实状态，不读出装饰性 Harness 品牌噪声。
- `prefers-reduced-motion` 下取消非必要动画。
- 200% 缩放和窄屏下不丢关键操作，不产生双向滚动陷阱。

## 11. 审核证据模板

每个节点的交付记录使用以下格式：

```markdown
# <节点 ID> <名称>

- 执行模型：
- 关联需求/AC/Figma：
- 范围与非目标：
- 变更文件/模块：
- 领域与数据影响：
- 安全与隐私影响：
- 验证命令：
- 验证结果：
- 失败/边界用例：
- 视觉/无障碍证据（适用时）：
- 迁移与回退：
- 遗留风险：
- 审核结论：PASS / BLOCKED
```

证据必须可重放。若某检查因环境、账号或外部服务无法执行，节点状态保持 `BLOCKED` 或明确降级为 Spike 结论，不能写成“已验证”。

## 12. 缺陷分级与发布规则

| 等级 | 定义                                                       | 处理                                            |
| ---- | ---------------------------------------------------------- | ----------------------------------------------- |
| S0   | 数据不可恢复丢失、凭据泄露、越权、审计链失真、双主执行     | 立即阻断全部依赖节点与发布。                    |
| S1   | AC 主链不可完成、重启重复执行、无法接管/取消、关键状态误导 | 阻断阶段出口和候选版本。                        |
| S2   | 有安全替代路径的功能缺陷、明显可访问性/响应式问题          | 节点原则上不关闭；例外需 Human 接受并限定版本。 |
| S3   | 不影响任务完成的文案、轻微视觉或低频体验问题               | 可带入候选清单，但必须有 owner 和目标版本。     |

R3/S0/S1 问题不能通过关闭测试、改预期或标记“已知限制”绕过。
