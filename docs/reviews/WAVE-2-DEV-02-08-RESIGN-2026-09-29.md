## 重签原因（一句话）

初版结论写的是「35 条攻击全部拦截，0 绕过」。**那句话不完整**——
那 35 条攻击**全部是 UPDATE 语义**，整类「创建轴」绕过从未被尝试。
独立审核指出后实测确认：消息可以**直接以 `DELIVERED` 状态诞生**，
投递记录可以**直接以 `SUCCEEDED` 诞生且 `completed_at` 为空**。
本轮新增 `0018` 补上该缺口后重签。

**这不是「漏判了结果」，是「根本没做这个尝试」。** 详见 DEV-02-09 判断日志 J17。

### `0018` 补的三个洞

| 洞 | 说明 | 语义来源 |
|---|---|---|
| 状态机创建入口 | `messages` 只能以 `DRAFT` 诞生；`delivery_attempts` 只能以 `PENDING` 诞生 | §5「创建 → DRAFT」「每次 attempt 单独记录 PENDING → IN_FLIGHT → …」 |
| 终态时间戳 | 创建时与状态不匹配的时间戳被拒；UPDATE 侧同样——`ROUTED → QUEUED` 时顺带写 `delivered_at` 也被拒 | §5 状态顺序 |
| **快照冻结的中间缝** | `0017` 只在**离开 DRAFT 后**冻结快照，从不在**离开 DRAFT 时要求**快照存在。DRAFT→QUEUED 可以不带任何快照 | §5「DRAFT → QUEUED 的副作用是冻结内容，记录 sender Binding snapshot」 |

第三项是 `0018` 的存在才暴露的：原测试直接以 `QUEUED` 插入，恰好被 `0017` 的 INSERT 守卫挡住；
一旦强制以 DRAFT 诞生，这条路径就裸奔了。

## 既有测试的修正（4 个文件，**不是迁就实现**）

`0018` 生效后，四个既有测试文件暴露出**它们自己在断言违反冻结规格的写入**：

| 文件 | 原写法 | 修正 |
|---|---|---|

| `artifact_reference_consistency_forward_migration.rs` | 2 处以 `DELIVERED` 插入消息作引用主体 | 状态与该测试无关，改为 `DRAFT` |
| `artifact_reference_upgrade_migration.rs` | 1 处同上 | 同上 |
| `event_outbox_consistency_forward_migration.rs` | 1 处同上 | 同上 |
| `thread_message_delivery_migration.rs` | 7 处 MessageRow `status: "QUEUED"`；2 处 attempt 直插 `IN_FLIGHT` | 全部改为 DRAFT/PENDING 起点 + 显式迁移 |
| `notification_attention_migration.rs` | Attention 指向从未创建的 `task_id` | 补建真实 Task 行 |

**判据**：改完之后测试仍能失败（移除 `0018` 必挂），且断言的是规格明文而非实现行为。

它直接以 `QUEUED` 插入，被 `0018` 短路后就不再检验快照规则了。已重写为「插 DRAFT → 迁移到 QUEUED」，
使断言真正落在快照规则上。
