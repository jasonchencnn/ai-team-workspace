# ADR-0006：macOS Adapter 脱组后代的生命周期边界

- 状态：**Accepted；Mock 定向证据通过，完整门禁待完成**
- 日期：2026-09-28
- 关联：DEV-03-02、Wave 2 Mac 正式验收 AD-01、ADR-0005
- 决策依据：Human 于 2026-09-28 明确授权总控决定全部技术实现原则并快速推进至 Wave 2 实现；总控在该授权范围内选择下述路线 2。此授权不包含发布、部署、外部付费或生产数据操作。

## 待决问题

冻结的 Adapter V0 协议要求 Adapter 在 EOF 或 `adapter.shutdown` 时清理自己创建的子进程，平台在 grace period 后可强制终止。DEV-03-02 的门禁同时要求孤儿进程清理可控。首轮验收发现：直接 Adapter 退出后，它以 `setsid()` 创建的新 session 后代继续存活。

当前修复将 Adapter 放入独立 macOS 进程组，退出、超时和 Drop 时向该组发 `SIGKILL`，同组后代的负向测试已通过。独立复审再次证明 `setsid()` 后代仍可逃离该组。macOS `launchd.plist` 的 `AbandonProcessGroup` 机制也只处理相同进程组，不能作为此反例的完整修复。现有无特权 supervisor 无法在父进程退出并被重新收养后，可靠地从进程树识别任意主动脱组后代。

## 决策与备选路线

1. **继续要求平台强制回收任意脱组后代。** DEV-03-02 保持 `BLOCKED`；先设计并验证具有进程创建约束或可追踪执行身份的 macOS 执行隔离层。该路线可能需要新的系统能力、权限、签名/entitlement 与技术栈决策，必须另行评估后再实施。
2. **按受批准 Adapter 的契约责任验收（采用）。** 平台保证直接子进程有界终止和回收，并对同组后代发出清理信号；每个受批准 Adapter 必须以真实子进程/脱组反例证明 EOF、关闭和崩溃后的清理策略，并把仍由外部服务持有的任务交由对账流程处理。任意恶意 Adapter 主动脱组的后代不被宣称为平台可强制回收。

路线 2 的准入材料为：每个待启用 Adapter 的已批准 manifest/entrypoint；真实 Mac 上正常 EOF、grace 超时、直接进程崩溃和 detached 子进程的有界测试；退出后 PID 不存在的证据；外部任务的 `UNKNOWN`/reconcile 记录；以及最终输入的完整 Mac Gate。Adapter 必须自行安排 detached 子进程在父进程失联时退出，平台不得把仅杀同组进程当成这个证据。新 Adapter 未通过上述检查不得进入已批准列表。无子进程的 Adapter 应以实际执行路径与故障注入证明该事实；一旦新增子进程，须重新准入。

本决策仅定义受批准 Adapter 的生命周期责任，**不放行 DEV-03-02**。Mock 的真实 Mac 脱组反例已在 EOF、强制关闭和直系崩溃路径定向通过，且由未参与实现的 Terra 复核；完整 Mac 门禁与总控终审尚须完成，节点继续 `BLOCKED`。任何新真实 Harness 的进程、远端任务和恢复行为仍逐 Adapter 审核，不从 Mock 的结果外推。开发中若发现无法可靠清理脱组后代，该 Adapter 禁止启用，节点或相应接入节点保持 `BLOCKED`。

若选择路线 1，下一步交付应先是 Mac 执行隔离层的可验证设计和权限/签名清单：证明 Adapter 不能创建不受追踪的新 session，或证明新 session 在父进程消失后仍可被唯一识别、强制终止并回收；之后才允许实现与门禁变更。普通进程组、`launchd` 同组清理或周期性 `ps` 快照都不能单独满足该证明。

## 代价、回退与复审

平台不提供对恶意 Adapter 及其任意脱组后代的强制隔离保证，因此入口审批和每个 Adapter 的真实负向测试是安全边界的一部分。若未来必须运行不可信 Adapter，或某个获准 Adapter 无法按契约退出脱组后代，暂停该入口并另立隔离 ADR；不得仅以周期性进程扫描代替证明。回退本决策时恢复路线 1 的严格阻断口径，DEV-03-02 回到 `BLOCKED`，不删除已有测试与证据。

本 ADR 不改写 Adapter V0 的领域协议字段，也不降低 G0～G9；仅明确 G8 在 DEV-03-02 上的责任归属与准入证据。Linux 不在本轮验证范围。
