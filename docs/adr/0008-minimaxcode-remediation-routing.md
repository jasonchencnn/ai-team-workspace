# ADR-0008：Minimaxcode 接续整改与后续开发的模型路由记录

- 状态：**Accepted（仅记录 Human 已明确给出的路由决策）**
- 日期：2026-10-08
- 直接授权：Human 要求“直到所有内容审计完成，然后制定下一步开发计划，继续由 minimax 完成，你要制定任务表，我转发给 Minimaxcode”。
- 替代范围：ADR-0004 对本轮接续任务主责模型的偏好；不追溯改写历史模型或审查事实。

## 已明确的决策

本轮审计后，由 Minimaxcode 主责总控签发的既有缺陷整改包和后续满足准入条件的开发包；Human 转发 Markdown，Codex 不直接调用或联系外部模型。Minimaxcode 是 Human 指定的执行环境，不假定它就是 MiniMax-M3、mmx CLI 或另一已知版本；每包启动回填实际 Harness、模型/版本、输入和访问条件。

Codex 总控继续负责冻结语义、任务拆分、依赖/写集、根 manifest/lockfile 串行整合、R3 独立反例复核和正式节点状态。Minimaxcode 只报告 SELF_CHECK_PASS / SELF_CHECK_BLOCKED，不自行宣布 DONE，也不能用自己的重复审查替代总控独立复核。

栈、领域状态、权限、wire 错误码、当前 Mac 门禁、零新增费用条件、只读 sources/旧迁移/历史证据及不提交/推送/部署/访问生产数据的限制继续有效。既有 BLOCKED 节点可按授权修复缺陷，未满足依赖的新节点仍是条件计划；没有开放 V2 新语义或发布。

## 独立的未决事项

本路由授权**不代表**接受 ADR-0007、同意在线审计/下载/外部账号操作，或认可未通过的节点。任何新的栈、状态/权限/协议含义仍须具体 ADR 和 Human 明确确认；不因 Minimaxcode 成为主责而放宽。

## 回退与验收

输出偏离任务包、违反冻结语义、写集冲突、S0/S1、模型/输入来源不明或门禁未通过时，该包保持 BLOCKED，停止依赖推进并回传证据，由总控决定修复或重新分配。保留所有历史交付，不 reset 或删除继承工作树。
