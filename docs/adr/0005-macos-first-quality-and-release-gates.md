# ADR-0005：先完成 macOS，再扩展其他平台的测试与发布门禁

- 状态：Accepted
- 日期：2026-09-28
- 决策者：Human Owner（2026-09-28 明确授权修改门禁，并确认「先完成 Mac」）
- 关联节点：DEV-01-05、Wave 2 收口、DEV-08-06～08
- 适用期：从本决策起，至首个 macOS 版本通过 Gate I 且 Human 明确批准发布；此后其他平台仍须按下文单独准入

## 背景与取舍

产品当前在 Mac 本地开发，macOS 14+ 是首个完整验收和发布目标。ADR-0001 原要求 Rust 核心同时在 Ubuntu CI 验证；ADR-0003 为零 GitHub Actions 预算建立 macOS ARM64 + Oracle Ubuntu ARM64 同快照门禁。后者额外引入远程容器、镜像来源、隔离和双端证据维护。它能发现跨环境问题，但不是 macOS 产品功能成立的必要条件，且当前工作区变化已使旧双环境证据失效。

Human 选择先完成 macOS 产品和发布验收，再为其他环境设立测试及上线标准。接受的代价是：现阶段不取得 Linux 构建/运行回归证据，不能声称 Linux、Windows 或 Intel Mac 已获支持；没有 GitHub branch protection 服务端强制时，节点放行仍依赖总控审核证据。

## 决策

1. **当前唯一阻断性平台是 macOS。** 开发节点按其专属标准及 G0～G9 验收；Gate B 与旧 Wave 2 收口只要求当前最终输入在本机 macOS ARM64 完成可复核门禁，不再要求 Ubuntu、Oracle、Docker 容器或双端输入哈希。此变更替代 ADR-0001 第 10 项的「核心同时在 Ubuntu CI 验证」、ADR-0003 的双环境放行条件，以及 ADR-0004 对该条件的引用；不改领域、权限、协议、数据和独立复核要求。
2. **Mac 门禁内容不减。** 在同一最终输入上运行冻结工具链的 `scripts/ci/local-gates.mjs --platform macos` 全部 21 项；保留完整输入清单及总 SHA-256、运行前后哈希一致性、命令/退出码、工具版本与来源、证据文件校验和。真实非 shallow Git 仓库仍须对全部 refs 执行 Gitleaks history 扫描并记录范围、配置、退出码及日志哈希。格式、Lint、类型、TS/Rust 测试、构建、Clippy、生成漂移、秘密、漏洞、许可证和 Rust unsafe 均保持阻断性。
3. 每批节点先做与改动匹配的本机定向验证；关闭节点或阶段时，针对最终输入运行完整 Mac 门禁。输入或安全公告库等门禁条件变化使相应旧证据失效。独立 R3 反例审核、失败注入、节点依赖和总控正式 `DONE` 判定保持不变。历史 Ubuntu 结果可作参考，不能补足当前 Mac 证据，也不再阻断节点。
4. GitHub workflow 的 required job 仅覆盖 macOS；原 Linux Docker `actionlint` 步骤改为 Mac 上的 YAML 格式/语法检查与仓库静态契约检查。在私有仓库零 Actions 预算阶段，本机证据是正式门禁，workflow 绿灯和 branch protection 均不得虚报。保留 Ubuntu Dockerfile 和已有历史证据供以后评估，但不运行 Oracle 或其他外部服务以完成当前 Gate。新增费用上限继续为 `$0`。
5. **macOS 上线仍须完整 Gate I。** AC-01～12、真实桌面 E2E、性能、安全、恢复、无障碍、安装/卸载、空库初始化、升级、备份恢复及签名前检查必须按现有 DEV-07/08 标准验证；S0/S1 和 R3 阻断项为零。若首发声明支持 macOS 14+，须在最低支持版本与首发目标架构上取得实机或等效受控环境证据；仅在当前开发机通过不能推断所有 14+ 版本可用。正式发布、签名、公证、部署或任何可能收费的动作仍需 Human 单独明确授权。Mac 门禁通过不自动等于产品已可上线。
6. 首个 macOS 版本通过 Gate I 并获得 Human 发布决定后，才能把其他平台列入正式支持目标。每新增一个平台/架构，先由 Human 接受平台范围及对应 ADR/节点，再建立该平台的 CI 或受控本地证据、完整应用构建与安装/卸载、进程/路径/凭据差异、安全、恢复、真实桌面 E2E、性能和发布产物验收。仅有 Rust 核心编译或容器测试不能宣称桌面平台可上线；该平台未通过前不阻断已获准的 macOS 发布。

## 其他平台的后续准入标准

下表现在作为后续平台任务的最低模板，不表示 Linux、Windows 或其他 Mac 架构已获准开工或发布。具体 OS 最低版本、CPU 架构、分发格式和验证环境须在该平台 ADR 中冻结。

| 阶段     | 阻断性证据                                                                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 范围冻结 | Human 确认支持矩阵、目标用户、安装包格式、费用及维护责任；列出与 Mac 的路径、凭据、进程、窗口和系统权限差异。                                                        |
| 工程门禁 | 目标平台/架构在固定工具链下完成完整源码构建、静态检查、自动测试、契约、生成漂移、秘密、漏洞和许可证检查；保存输入与产物校验和。                                      |
| 本机能力 | 在真实目标系统验证安全存储、Adapter 启停/取消/崩溃恢复、Git worktree/路径隔离、SQLite 迁移/备份恢复、Tauri capability 和权限提示。容器内 Rust 测试只覆盖其中一部分。 |
| 产品验收 | 使用真实桌面应用完成适用 AC、失败注入、性能、键盘/读屏及窄屏检查；记录最低支持版本与架构的结果。                                                                     |
| 发布判定 | 验证安装、升级、卸载、数据保留/回退、签名或发行渠道要求、已知限制和支持文档；无 S0/S1 或未关闭的 R3 阻断项，由 Human 单独批准该平台发布。                            |

Linux 需额外覆盖选定发行版的桌面依赖、Secret Service、文件权限与子进程信号；Windows 需覆盖 Credential Manager、路径/大小写/长路径、进程树终止与安装包权限。这些是未来平台 ADR 的输入，不提前宣称支持。

## 影响与迁移

- DEV-01-05 已有双环境工作与审核记录保留为历史事实，不追溯改写。自本 ADR 起，后续节点和旧 Wave 2 的正式放行按 Mac 单环境证据执行；`REVIEW/BLOCKED` 不因规则变更自动转为 `DONE`。
- 现行开发基线、Gate B、节点表、Wave 2 收口计划、协作入口与 CI 静态契约按此决策同步；归档快照和旧审核记录不改写。
- 若 Mac 门禁或独立审核失败，节点保持 `REVIEW/BLOCKED`。若未来要恢复 Ubuntu 为 macOS 发布的阻断门禁，必须由 Human 接受新的或替代 ADR，列明目标、成本、证据和回退方式。

## 验证标准

1. 当前文档、workflow 与静态契约不再把 Ubuntu 作为 Mac 节点或发布的 required check。
2. Mac 的 21 项完整门禁、全 refs 历史秘密扫描、同输入证据及独立审核仍能阻断正式 `DONE`；未实际运行时明确记为待验证。
3. DEV-08 的 macOS 产品级 Gate I 与 Human 发布决定保持独立，其他平台没有未经验证的支持声明。
