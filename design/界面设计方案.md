# AI Team Workspace 界面设计方案

日期：2026-09-20。依据：《多 Harness AI 开发团队协作平台 PRD》V1.0。

## 设计方向

面向 Human 产品负责人，以“团队席位”建立识别：岗位名称和岗位标识始终固定，Harness 是其下方可切换的执行绑定。首页以真实团队分工为主体，并列呈现任务与共享文件，帮助用户判断谁在工作、哪里受阻、自己需要处理什么。

审美 skill：anthropics/skills 的 frontend-design，已安装到本机并读取。采用清晰中文排版、浅色工作面、稳定左导航、有限的状态色。避免将首页铺满无关统计卡片，把视觉重点留给团队席位及工作流。

设计复核：通用管理台常将 KPI 放在首屏；本产品以岗位工作关系作为首页主体。状态、执行者和当前任务分别展示，避免把“在线”误读为“任务完成”。Harness 品牌采用文本标识，保持岗位的视觉优先级。

## 页面与内容

1. 团队空间：项目 Nova，账号系统迭代；Leader、产品、前端、后端四个稳定席位；当前绑定与工作状态；待 Human 决策；共享文件与最新活动。
2. 任务面板：全部／待开始／执行中／受阻／待验收／已完成筛选，看板与列表入口。任务卡显示负责人岗位、任务 ID、文件引用和依赖，不复制需求正文。
3. 任务详情：FE-023 登录界面；负责人前端、绑定 MiniMax；需求引用、结果、执行记录、阻塞与处理入口。Task 状态和某次执行状态分开展示。
4. 岗位与绑定：岗位职责、权限摘要、当前 Harness 和绑定历史。未绑定、在线、离线三种状态可识别。
5. 更换 Harness：保持前端岗位身份，选择 Claude Code；运行中任务处理采用“完成后更换／取消并重新执行／人工接管”。默认选择完成后更换，明确待生效，不能伪装为立即完成。
6. 文件空间：目录树、Markdown 阅读面、关联任务和版本信息；任务点击可直达文件章节，文件也能回到引用它的任务。
7. 待我处理：分别组织产品决策、验收、权限审批、执行异常；操作前显示影响范围，提供处理和查看依据入口。
8. 窄屏方案：岗位与任务单列，导航收纳；关键动作保持可见，任务详情成为全屏页。复杂团队总览以桌面为主要工作形态。

## 主要交互链

团队席位 → 岗位详情 → 更换 Harness → 检查运行中任务 → 确认策略 → 显示待生效绑定 → 完成后新绑定生效。

任务面板 → FE-023 → 需求文件 → 任务结果 → 发起验收 → 通过或退回。完整需求只在文件中维护；卡片和详情提供引用入口。

待我处理 → 产品问题 → 阅读问题文件 → 写入决策 → 恢复任务。UI 明确展示恢复后的负责人岗位。

## 控件与状态规范

- 按钮：主操作、次操作、危险操作、不可用、键盘聚焦。每一区域仅一个主操作。
- 岗位席位：岗位身份、当前绑定、在线情况、当前任务、下一步动作；换绑后岗位颜色与名称保持一致。
- 任务：以文字标签配合颜色标识 TODO、READY、DOING、BLOCKED、REVIEW、DONE、CANCELLED，取消任务默认收纳。
- 空团队：提示创建岗位并选择工作空间；无任务：创建任务；未绑定岗位：绑定 Harness；无文件：创建入口文件。
- 加载：骨架与就地进度；失败：保留已有内容，显示重试；断连：显示最近更新时间，禁止误显示为实时。
- 更新冲突：说明“任务已被更新”，提供刷新对比；权限不足：显示申请入口；文件失效：显示修复引用入口。
- 交互响应 120–180ms；尊重减少动态效果；颜色不作为唯一状态信息。

### 已连接的演示路线

| 入口 | 演示流程 | 业务约束 |
|---|---|---|
| 团队空间 | FE-023 → 任务详情 ⇄ 关联 Markdown 文件 | 结构化任务不复制需求正文 |
| 前端席位／岗位导航 | 前端岗位 → 更换 Harness → 已安排更换 | 默认当前执行结束后生效，岗位身份保留 |
| 任务详情 | 人工接管 → 请求停止并接管 → 已进入人工接管 | 成功画面以旧执行已停止且写入权限已撤销为前提 |
| 待我处理 | 7 天有效期 → 保存决策并恢复任务 → 决策已记录 | 解除阻塞不等于完成任务 |
| 任务面板 | 创建任务 → 预填任务摘要 → 创建并分配 → 待开始 | 创建成功不等于 Harness 已开始执行 |
| 空状态 | 创建第一项任务 → 预填任务摘要 | 用明确行动解释下一步 |
| 状态变更通知 | 管理订阅 → 通知订阅与投递策略 → 查看线程审计 | 按稳定 Role 订阅；去重和重试不改变 Event 事实 |
| 换绑待生效 | 查看待投递消息 → 换绑期间待投递消息 → 返回岗位通信 | 已入队消息保留 Binding 快照；后续投递解析当前有效 Binding |
| Harness 连接 | 健康检查／实例诊断 → Harness 注册与健康检查 → 返回连接列表／查看审计 | 凭据仅保留安全引用；不改变 Role、权限或历史 Binding |
| 消息投递异常 | 查看失败详情 → 消息投递终态 → 重试、改派、新建后续消息或查看审计 | `RETRYING` 为瞬态；`FAILED`、`EXPIRED` 保留原消息与审计链 |

### 原型范围与实现差距

本次为第一版可编辑视觉方案及关键路径原型，不是全部 PRD 功能的可运行前端。浮层在原型中以独立画板跳转演示；开发时应实现真实对话框的遮罩、焦点锁定、Esc 关闭和返回焦点。

- 演示是状态快照。反馈后的返回操作回到演示基线，不会持久修改其他画板的数据。
- 仅演示默认的“执行结束后换绑”和“7 天决策”分支；其余选项显示设计意图，未模拟完整分支。
- 首版“创建任务”保留为预填摘要确认；审计整改版已增加负责人、文件引用、依赖和 TODO/READY 校验规则的完整表单状态。它仍是原型数据，开发前需补可编辑输入控件、选择器、错误和加载状态。
- 筛选、看板拖拽、全局搜索和实时日志尚未实现完整可点击逻辑；验收、权限审批、失败重试、对账、依赖冲突和岗位通信已增加关键状态画板。
- 窄屏交付为待处理概览；按钮连接桌面决策画板，尚不是完整的移动端闭环。
- 文中加载、断连、权限不足、引用失效和并发冲突规范作为后续详细设计要求；目前未逐一制作独立高保真画板。

### 验证记录

2026-09-20 已逐页截图复核全部 16 个画板，修复多行文本高度、导航底色与看板换行问题；同步任务统计为 2 个执行中、2 个待验收、1 个受阻。文件页与任务详情的关联可双向跳转。

2026-09-21 审计整改后先后复核 36 个画板：无直接子层越界，所有可见文字均为 Noto Sans SC，129 条 Node 原型反应均指向有效节点。第三轮整改补充了 Harness 注册与健康检查、默认通知类别覆盖、消息 `FAILED / EXPIRED` 终态和 7 个关键画板的主操作跳转闭环。

结构检查：610 个可见文字节点均使用 Noto Sans SC；211 个组件实例；36 个画板的直接子层均未超出画布边界；129 条 Node 原型反应无无效目标，12 条 Hover 均指向有效组件变体。此检查不等同于浏览器端响应式、无障碍或真实业务测试。

后续建议：先评审岗位/任务/文件三者的信息关系与本版视觉风格；确认后补完整表单、权限及异常状态，再依 PRD 接入真实 Harness、文件系统与事件接口。节点索引保存在同目录 `figma-state.json`，可继续迭代而无需重建设计文件。
